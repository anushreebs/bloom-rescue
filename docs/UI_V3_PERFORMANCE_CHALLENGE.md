# Performance challenge round

Reviewed shared round-one synthesis and all three actual static HTML directions after independent baseline work.

## Twelve requested questions

1. **Senior craftsmanship?** Concept A's clearer typography and systematic surfaces are credible direction; static attractiveness cannot establish production craft. Working recovery and restrained motion matter more than spectacle.
2. **Distinctive?** Evidence/editor relationship is more product-specific than a generic dashboard. Decorative differentiation alone does not justify B's extra effects.
3. **Blocked application immediately?** Question and state-specific next action improve scannability; only a user test can establish seconds-to-identification.
4. **Suggestion understandable?** Generated/edited/approved provenance is stronger than a generic AI badge. Preserve exact-excerpt limits.
5. **Evidence intuitive?** Beside-editor supports comparison. Do not collapse critical source to buy whitespace.
6. **Actions visible?** Concept A approval is prominent, while submission stays separate. Need live narrow-screen check.
7. **Motion improves understanding?** State-linked feedback plausibly does; measured benefit unknown. Real requests must remain the only clock.
8. **Excessive?** Repeated hero/receipt animation on revisit would overstate novelty and distract. New-receipt-only motion preferred; avoid re-mounting editor for entrance choreography.
9. **Genuinely fast?** Not established. Current baseline has small payload and no observed >50ms long tasks in six short local sessions; neither is field INP, LCP nor60fps evidence.
10. **Trust outcome?** Verdict-specific copy and supplemental-warning separation fix consequential misleading messages. No performance shortcut justifies false success.
11. **Every state accessible?** Unknown until final QA; static concepts cannot pass accessibility. Both themes must be scanned and keyboard-tested.
12. **Maintainable?** Native CSS/SVG, stable components and bounded session buffers are manageable. Keep source-of-truth state independent of animation state.

## Debate and decision

**Strongest other proposal:** Revision-aware session-only answer buffers from UX/frontend preserve edits without persisting personal answers to disk. Benefit is concrete from observed `open()` reset. It adds a small map and checks, not a performance concern for five fixtures.

**Weak proposal challenged:** Rich dimensional/ambient treatment of B is not supported by a recovery task need. Shadows and subtle selection offsets are cheap enough alone; reject continuously animated blur or multiple expanding cards absent evidence. A dark palette can be borrowed without B's visual mechanics.

**Tradeoff:** URL-backed navigation and state buffers add complexity, but context retention is user-facing and testable. Compare that value to decorative effects first. Dark mode roughly doubles contrast-verification surface; ship only if both themes are actually checked, otherwise defer.

**Changed recommendation:** Initially dark mode was simply a possible cheap token change. After the synthesis, support it conditionally alongside A only when full semantic colors—not selective global inversion—are implemented and both-theme tests pass. Keep100KiB JS gzip project budget. Do not memoize every control or add libraries to chase unmeasured rerender costs.

**Limits / evidence changing decision:** Final mobile traces showing long tasks or theme contrast errors justify reducing effects or deferring dark mode. Real interruption/layout needs and measured library cost could justify a motion dependency later. No quantitative visual score is independent evidence; weightings are subjective design judgments.
