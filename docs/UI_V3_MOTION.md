# Motion director — independent round 1

## Evidence and three findings

1. **Preserve: state accuracy comes before choreography.** Observed in `App.tsx` and `WorkspaceVisuals.tsx`: draft generation, approval and resume are separate calls; the progress labels distinguish missing evidence from a completed evidence check; the submitted outcome explicitly says mock ATS. The spinner is generic pending feedback, not fictional model reasoning. No measured comprehension result establishes this is intuitive to users.
2. **Opportunity: motion currently explains entrance more than causality.** Observed in `styles.css`: queue entrance is 320 ms with 35 ms item staggering, hover moves cards 2 px, illustration parts animate for 600–700 ms, evidence and outcomes enter, and the receipt check draws. `App.tsx` does not key the workspace by selected ID, so switching applications does not reliably create a distinct destination entrance. Existing immutable card order preserves position. The screenshot `artifacts/ui-redesign/supported-draft-desktop.png` confirms adjacent evidence/editor hierarchy, but a still cannot establish animation quality. Hypothesis: a modest selection-to-workspace transition would improve orientation more than additional ornamental motion.
3. **Preserve and strengthen: reduced motion has a real static end state.** Observed `prefers-reduced-motion` disables transitions/animations and forces the check stroke complete. This is stronger than merely shortening animations. Existing shadow and border transitions can cause painting; they are bounded cards, not an established bottleneck. No runtime profiling or assistive-technology test was performed by this role.

## Language and implementation rules

Native CSS first. Use `--motion-fast: 140ms`, `--motion-panel: 220ms`, `--motion-state: 280ms`, `--motion-signature: 420ms`; enter easing `cubic-bezier(.22,1,.36,1)`, feedback easing `cubic-bezier(.2,0,0,1)`. A spring library is not justified for five cards and three state surfaces. Do not bounce important text or animate textarea dimensions. Prefer transform/opacity; no perpetual gradient, blur, parallax, typing simulation or percentages without measured progress. Do not delay API execution or artificially hold a fast response for animation. Duration values are design hypotheses, not performance results.

## Implementation priorities

- **Must:** preserve truthful pending/error/uncertain states and static reduced-motion receipt. No choreography blocks controls, hides evidence or delays requests.
- **Should:** coherent motion tokens; selection-keyed visual entrance; state-specific outcome arrival; receipt animation keyed by receipt ID; button press/focus parity.
- **Optional:** subtle source-context chevron rotation. Do not add FLIP queue sorting until an actual filter/grouping requirement exists; stable positions are clearer now.

## Strongest counterargument

The existing UI already animates queue, illustration, feedback and outcome, so additional motion may add distraction without task benefit. Agree that adding animation count is the wrong objective. Adopt only causal selection/evidence/outcome transitions and shorten the large illustration sequence. Keep all information available immediately. If user testing shows no orientation benefit or profiling identifies dropped frames, remove the transition rather than expand the dependency stack.

## Confidence, verification and limitations

High confidence in code-level observations; moderate confidence in the proposed motion language; low confidence in claimed user benefit until tested. This role inspected source and one actual screenshot, not a new live recording. No new Figma edits, production performance measurements, screen-reader checks or animation playback test performed. Frontend/QA should verify normal and reduced-motion selection, fast and delayed responses, rejected approval, missing evidence, uncertain submission, refresh and repeated navigation. A screenshot cannot prove these interactions passed. Motion must be judged in an actual recording plus browser traces, with input latency unaffected by visual duration.
